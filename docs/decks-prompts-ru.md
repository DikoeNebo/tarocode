# Промпты колод (RU)

Источник в приложении: `data/locales/ru/*.json`.

Пять встроенных колод:

- `validate-v1` — 01 Валидация
- `spec-v1` — 02 Спецификация
- `lazy-v1` — 03 Работа · Хобби
- `pro-v1` — 03 Работа · Продакшен
- `release-v1` — 04 Релиз

Ниже — тексты рабочих колод. Новые фазовые колоды правь сразу в JSON (поля `title` / `description` / `prompt`). Правки в этом файле **не подхватываются сами**.

## Колода: 03 Работа · Хобби (`lazy-v1`)

### 1. План · F1 · `plan` · hierophant

**Описание:** Иерофант: разбей задачу на шаги — пока без кода

**Промпт:**

```
Составь пошаговый план по текущей задаче. Код не пиши.

Из чата (спрашивай только если нет): итог одной фразой; что уже есть; простой хобби-проект без лишней сложности.

Правила:
1. Мелкие шаги — один шаг = одна проверяемая вещь.
2. У шага: что · «готово» · как проверить.
3. Сначала блокеры; риски / что отложить.

В конце — нумерованный список шагов (одна строка на шаг).
```

### 2. Оцени · F2 · `evaluate` · justice

**Описание:** Справедливость: балл оценки проекта 0–10 и вердикт

**Промпт:**

```
Оцени текущий план или последний результат честно, без воды и лести.

Балл оценки проекта 0–10: 0–6 переделать; 7–8 приемлемо; 9–10 отлично. Ниже 7 — обязательно переделать; ≥7 можно продолжать.

Проверь: цель/«готово» ясны? дыры? лишняя сложность для хобби? что сломается первым? топ-3 правки для балла.

Ответ:
- Балл оценки проекта: N/10
- Вердикт: переделать (<7) / приемлемо (7–8) / отлично (9–10)
- Плюсы · минусы/риски · конкретные правки

Не предлагай всё с нуля, если хватает точечных правок. Код не начинай, пока не попросят.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 3. Работай · F3 · `work` · magician

**Описание:** Маг: сделай следующий шаг плана в коде

**Промпт:**

```
Сделай следующий незакрытый шаг утверждённого плана — только его, не всё сразу.

Правила: если шаг неочевиден — назови и делай его; не ломай рабочее; нет данных — спроси коротко, не выдумывай. После: что · где · как проверить.

В конце одной строкой: статус шага — готово / частично / блокер (и почему).
```

### 4. Тест · F4 · `test` · star

**Описание:** Звезда: проверь результат фактом, не словами

**Промпт:**

```
Протестируй то, что только что сделано (последний шаг или явно названная часть).

Сделай: релевантные проверки (команды/сборка/ручной сценарий); покажи факты; на падении — причина + минимальный фикс; на ок — «ТЕСТ ПРОЙДЕН» + что проверено. На красном к следующему шагу не переходи.

Итог: зелёный / красный + одна фраза почему. Добавь предварительный балл оценки проекта 0–10 (ниже 7 = ещё не готово).

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 5. Исправь · F5 · `fix` · tower

**Описание:** Башня: почини поломку до приемлемого балла (≥7)

**Промпт:**

```
Исправь проблемы по последнему тесту, ошибке или баллу оценки проекта ниже 7/10.

Только минимальный фикс — без рефакторинга «заодно» и новых фич. Симптом → причина → патч → проверка. Цикл, пока балл ≥ 7. Если стена — блокер + 2 выхода. Кратко: было → сделал → убедился.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 6. Доведи · F6 · `polish` · strength

**Описание:** Сила: поднимай балл оценки проекта до 9–10

**Промпт:**

```
Режим «Доведи». Не останавливайся, пока балл оценки проекта не станет 9 или 10 из 10.

7–8 для этой карты мало. Цикл без «продолжать?»: балл N/10 + главные дыры → правки только по ним → проверка → снова балл. Пока ≤ 8 — повторяй. Стоп только на 9–10.

Потом: итоговый балл · что подняло · что не трогал.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 7. Бэкап · F7 · `backup` · hermit

**Описание:** Отшельник: сохрани точку отката

**Промпт:**

```
Сделай безопасную точку отката текущего состояния проекта.

1. git status (или аналог).
2. Осмысленный коммит или готовая команда — без force и --no-verify без просьбы.
3. Нет git — копия ключевых файлов с датой в имени.
4. Откат 1–2 командами. Не пушь без просьбы.

В конце: «Точка сохранена» + куда/как откатиться.
```

### 8. Полный цикл · F8 · `fullcycle` · world

**Описание:** Мир: план → работа → тест, каждый шаг ≥ 7 баллов

**Промпт:**

```
Полный цикл по плану от начала до конца — без перескоков.

Пункт закрыт только при балле оценки проекта ≥ 7 (для 9–10 — «Доведи»). На пункт: назвать → сделать → проверить → балл → если <7 исправить до ≥7 → дальше. Не раздувать задачу.

Нет плана — сначала короткий на 5–8 шагов (или сразу, если уже согласован).

Финал: общий балл · готово / не сделано · что проверить вручную. При общем <7 успех не объявляй.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 9. Сводка · клик · `summary` · high_priestess

**Описание:** Жрица: коротко — задача, сделано, не сделано, дальше

**Промпт:**

```
Прочитай этот чат и контекст репозитория. Код не пиши и не меняй.

Ответ строго в четырёх коротких блоках (в каждом 1–3 пункта):
1. Задача — что делаем (одна фраза + scope, если ясен).
2. Сделано — что уже реализовано или проверено.
3. Не сделано — открытые шаги, падения, блокеры, неясности.
4. Следующий шаг — одно лучшее действие (назови План / Работай / Тест / Исправь, если очевидно).

Если плана нет — так и напиши, рекомендуй «План». Неясное помечай явно — не выдумывай. Строку KEYCODE_SCORE не добавляй.
```

## Колода: 03 Работа · Продакшен (`pro-v1`)

### 1. План · F1 · `plan` · hierophant

**Описание:** Иерофант: план под merge-ready изменение, не черновик

**Промпт:**

```
Составь план реализации по текущей задаче. Код не пиши. Без воды.

Из контекста: критерии приёмки; scope IN/OUT; риски (данные, API, гонки, совместимость, регрессии).

Правила: мелкие проверяемые шаги с результатом + способ проверки; учесть тесты/ошибки/края/откат; простое рабочее > «идеальная» архитектура; явно — допущения и открытые вопросы.

Вывод: нумерованный план + короткий список рисков + definition of done.
```

### 2. Ревью · F2 · `evaluate` · justice

**Описание:** Справедливость: ревью с баллом оценки проекта 0–10

**Промпт:**

```
Строгое ревью текущего плана или diff/результата.

Балл оценки проекта 0–10: 0–6 блок; 7–8 приемлемо с оговорками; 9–10 высокая планка. Ниже 7 = блокер.

Проверь: корректность/края; регрессии; сложность; тесты/ошибки; безопасность/данные если уместно; топ-3 правки для PR.

Формат:
- Балл оценки проекта: N/10
- Вердикт: блок (<7) / приемлемо (7–8) / сильно (9–10)
- Findings: Critical / Major / Minor
- Конкретные правки

Крупный рефакторинг только по просьбе. Ниже 7 не принимать.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 3. Уточни · F3 · `improve` · temperance

**Описание:** Умеренность: сожми план до минимума для реализации

**Промпт:**

```
Доведи текущий план или дизайн до уровня готовности к реализации.

Вырежи всё вне acceptance criteria; уточни интерфейсы/данные/ошибки/тесты; если раздут — предложи проще с trade-offs; сохрани шаги + способ проверки. Код не пиши, пока не попросят.

Вывод: обновлённый план + changelog (3–7 пунктов) + балл готовности плана 0–10.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 4. Кодь · F4 · `work` · magician

**Описание:** Маг: следующий шаг — проверяемый код без регрессий

**Промпт:**

```
Реализуй следующий незакрытый шаг утверждённого плана.

Только этот шаг; без регрессий; ошибки обрабатывай явно; нет данных — 1–3 точных вопроса, не выдумывай API. После: что изменилось · как проверить · риски.

Статус: готово / частично / блокер + почему. Цель — уверенный балл корректности ≥ 7/10.
```

### 5. Тест · F5 · `test` · star

**Описание:** Звезда: докажи зелёным прогоном, не обещанием

**Промпт:**

```
Проверь то, что только что сделано, как в CI, а не «должно работать».

Команды/тесты/сборка с реальным выводом; happy path + один край/фейл (или почему нельзя). Красный — причина + минимальный фикс/блокер; зелёный — «ТЕСТ ПРОЙДЕН» + список проверок. На красном дальше не иди.

Итог: зелёный/красный + предварительный балл оценки проекта 0–10 (ниже 7 = не готово).

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 6. Фикс · F6 · `fix` · tower

**Описание:** Башня: минимальный патч до балла ≥ 7

**Промпт:**

```
Исправь дефект по последнему тесту, ревью или баллу оценки проекта < 7.

Только минимальный фикс. Симптом → причина → blast radius → патч → проверка тем же способом. Цикл до ≥ 7. Блокер — 2 варианта с trade-offs. было → стало → доказательство. Новые фичи пока дефект открыт запрещены.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 7. Доведи · F7 · `polish` · strength

**Описание:** Сила: поднимай балл оценки проекта до 9–10

**Промпт:**

```
Режим высокой доводки. Останавливаться на 7–8 нельзя. Цель — балл оценки проекта 9 или 10 из 10.

Цикл: балл N/10 + Critical/Major дыры → правки только по ним (scope freeze) → перепроверка → новый балл. Пока ≤ 8 — повторяй. Стоп только на 9–10.

Отчёт: балл · что подняло качество · остаточный риск · что не трогал. Если потолок <9 извне — назови после исчерпания правок в scope.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 8. Цикл · F8 · `fullcycle` · world

**Описание:** Мир: end-to-end, каждый пункт ≥ 7 баллов качества

**Промпт:**

```
Полный end-to-end цикл по плану.

Пункт закрыт только при балле оценки проекта ≥ 7 (для 9–10 — «Доведи»). На пункт: назвать → реализовать → проверить фактами → балл → чинить до ≥7 → дальше. Без перескоков, раздувания scope и маскировки красных тестов.

Нет плана — сначала короткий на 5–8 шагов с критериями приёмки, потом цикл.

Финал: общий балл · готово/не сделано · остаточные риски · что проверить вручную перед merge.

В самом конце ответа обязательно добавь строку (N = твой балл 0-10):
KEYCODE_SCORE: N
```

### 9. Сводка · клик · `summary` · high_priestess

**Описание:** Жрица: коротко — задача, сделано, пробелы, дальше

**Промпт:**

```
Прочитай этот чат и контекст репозитория. Код не пиши и не меняй.

Ответ строго в четырёх коротких блоках (в каждом 1–3 пункта):
1. Задача — цель + критерии приёмки, если известны.
2. Сделано — реализовано, отревьюено или проверено.
3. Не сделано — открытое, падения, блокеры, неясности.
4. Следующий шаг — одно лучшее действие (назови План / Ревью / Кодь / Тест / Фикс, если очевидно).

Если плана нет — так и напиши, рекомендуй «План». Неясное помечай явно — не выдумывай. Строку KEYCODE_SCORE не добавляй.
```
