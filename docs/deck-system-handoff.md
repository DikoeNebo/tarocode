# Handoff: Keycode (Тарокод) — как работают программа и колоды

Документ для передачи другому ИИ. Цель: понять продукт, цикл карт, скоринг и где лежат тексты промптов — чтобы править колоды или писать новые карты согласованно с системой.

Полные тексты карт (RU): `docs/decks-prompts-ru.md`  
Исходники колод: `data/locales/{locale}/lazy-v1.json`, `pro-v1.json`  
Спека продукта: `AGENTS.md`

---

## 1. Что это за программа

**Keycode (Lazy Coder / Тарокод)** — Windows-приложение (Electron). Поверх экрана всегда видна «колода» до 9 карт-промптов. Один клик (или F1–F8) вставляет текст выбранной карты в целевые чаты Cursor (и опционально в обычные поля других приложений).

Проблема, которую решает: vibe-coder’ы и программисты снова и снова вбивают одни и те же длинные инструкции («оцени», «почини», «протестируй»). Колода — готовый цикл этих инструкций.

**Не делает:** не выбирает карты нейросетью; не пишет код сама; не ходит в облако за чатами. Вставка в Cursor — через локальный CDP (Chrome DevTools Protocol), без кражи фокуса у игры/другого окна.

---

## 2. Как пользоваться (короткий сценарий)

1. Запустить Keycode; показать/спрятать колоду (глаз / F9).
2. Запустить Cursor с CDP (кнопка ◎ / «Restart with CDP», порт обычно `9222` на `127.0.0.1`).
3. В окне «Чаты» добавить один или несколько чатов Cursor как цели.
4. На полосе выбрать режим: **broadcast** (набор целей) или **solo** (один чат).
5. Кликнуть карту → полный `prompt` карты вставляется в выбранные чаты (+ Enter, если включено в настройках).
6. Агент в Cursor отвечает по тексту карты. Карты со скором обязаны заканчивать ответ строкой `KEYCODE_SCORE: N`.

Опционально: телефон на том же Wi‑Fi — веб-пульт (LAN), один выбранный чат Cursor, те же карты.

## 3. Что такое колода и карта

### Колода (deck)

- `id`, `name`, массив `cards` (1–9 штук).
- Две встроенные:
  - `lazy-v1` — «Тарокод · Хобби» (простые сайд-проекты, мягче).
  - `pro-v1` — «Тарокод · Продакшен» (жёстче, merge-ready / ревью).
- Есть пользовательские колоды (import/export JSON). Встроенные при смене языка UI перезаписываются из `data/locales/{locale}/`.

### Карта (card)

| Поле | Смысл |
|------|--------|
| `id` | Стабильный id (`plan`, `evaluate`, `work`, …) — от него зависят подсказки «следующей карты» |
| `title` | Короткое имя на карте |
| `description` | Подпись / аркан одной строкой |
| `prompt` | **Полный текст**, который вставляется в чат |
| `image` | id таро-картинки (hierophant, justice, …) |
| `hotkey` | `F1`…`F8` или пусто (только клик; обычно 9-я карта «Сводка») |

На полосе: клик или хоткей → один и тот же `prompt` уходит во все resolved-цели (broadcast) или в один solo-чат. Разный текст на разные цели за один клик — не поддерживается.

## 4. Балл оценки проекта (ядро логики)

Единая шкала **0–10** («балл оценки проекта» / project quality score):

| Балл | Смысл |
|------|--------|
| 0–6 | Плохо → **обязательно переделать** |
| 7–8 | Приемлемо, можно идти дальше |
| 9–10 | Отлично / высокая планка |

Правила продукта:

- Ниже 7 = redo / блок.
- Карта **«Доведи»** (`polish`) крутит цикл, пока не будет **9 или 10** (7–8 для неё мало).
- Карты, которые просят оценку/тест/фикс, в конце ответа агента **обязаны** дать машиночитаемую строку:

```text
KEYCODE_SCORE: N
```

где `N` — целое 0–10. Без этой строки подсказки следующей карты работают хуже (есть запасные regex по «Балл оценки проекта: N/10», но канон — `KEYCODE_SCORE`).

Карта **«Сводка»** (`summary`) — исключение: код не пишет, score **не** добавляет.

## 5. Типичный цикл карт

Это не жёсткий автомат UI, а **задуманный workflow** человека + правила подсветки.

### Хобби (`lazy-v1`)

| id | UI | Роль |
|----|-----|------|
| `plan` | План F1 | Разбить задачу на шаги, **без кода** |
| `evaluate` | Оцени F2 | Честная оценка плана/результата + score |
| `work` | Работай F3 | Один следующий шаг плана в коде |
| `test` | Тест F4 | Проверить фактами; зелёный/красный + score |
| `fix` | Исправь F5 | Минимальный фикс до score ≥ 7 |
| `polish` | Доведи F6 | Довести до 9–10 |
| `backup` | Бэкап F7 | Точка отката (git commit и т.п.) |
| `fullcycle` | Полный цикл F8 | План→работа→тест по пунктам, каждый ≥ 7 |
| `summary` | Сводка (клик) | Задача / сделано / не сделано / следующий шаг |

### Продакшен (`pro-v1`)

Тот же каркас, но тон жёстче + карта **`improve` (Уточни)** вместо бэкапа в середине цикла:

| id | UI | Роль |
|----|-----|------|
| `plan` | План F1 | Merge-ready план, acceptance, риски |
| `evaluate` | Ревью F2 | Строгое ревью + Critical/Major/Minor + score |
| `improve` | Уточни F3 | Сжать план до готовности к коду |
| `work` | Кодь F4 | Один шаг, без регрессий |
| `test` | Тест F5 | Как в CI, факты + score |
| `fix` | Фикс F6 | Минимальный патч до ≥ 7 |
| `polish` | Доведи F7 | До 9–10 |
| `fullcycle` | Цикл F8 | End-to-end по плану |
| `summary` | Сводка (клик) | Статус чата без кода |

**Пример потока:** План → Оцени/Ревью → (Уточни в pro) → Работай/Кодь → Тест → если score &lt; 7 то Исправь/Фикс → снова Тест → при желании Доведи → Бэкап (hobby) / merge-готовка.

## 6. Подсказки «какой картой дальше» (не ИИ)

Модуль: `electron/card-suggestions.js`.

Работает **только в solo-режиме** для CDP-чата (полоса + телефон). Смотрит транскрипт:

1. Какая карта была вставлена последней (по совпадению текста промпта).
2. Последний `KEYCODE_SCORE: N` (и запасные фразы балла).
3. Исход теста (например «ТЕСТ ПРОЙДЕН» / красный).

На колоде подсвечивает до **3** карт: 1 яркая (primary) + до 2 приглушённых (secondary). Пока Cursor генерирует — подсветка **заморожена**. В broadcast и без выбранного чата подсказок нет.

При правке промптов важно:

- Не ломать `id` карт без нужды (логика завязана на `plan`, `evaluate`, `work`, `test`, `fix`, `polish`, `improve`, `fullcycle`, `summary`, `backup`).
- Сохранять требование финальной строки `KEYCODE_SCORE: N` там, где карта оценивает/тестирует/чинит/доводит.
- Не добавлять `KEYCODE_SCORE` в `summary`.

## 7. Куда программа вставляет текст

**Режимы paste:**

- `broadcast` — во все цели активного пресета (или все включённые чекбоксы).
- `solo` — только в один выбранный чат (как на телефоне).

**Драйверы целей:**

- `cdp` — основной путь: Cursor через локальный debug-порт, без `SetForegroundWindow`.
- `uia-quiet` — тихое поле (ValuePattern), если «не забирать фокус».
- `win32-field` / `uia` — старый путь с фокусом, только если no-focus выключен.

Очередь вставок одна: карты с полосы и с телефона не должны гонять параллельно «вразнобой».

Телефон: список **всех открытых** чатов Cursor с CDP; карта/свободный текст всегда **submit** в выбранный чат; промпты в логи не пишутся.

## 8. Где править тексты

| Что | Где |
|-----|-----|
| Читать/править удобно (RU) | `docs/decks-prompts-ru.md` |
| Реальные данные приложения | `data/locales/ru/lazy-v1.json`, `pro-v1.json` (+ другие локали) |
| UI редактора | Настройки → Колоды → карта → поле prompt |
| Данные пользователя на диске | `%APPDATA%/keycode-lazy-coder/keycode-data/decks/` |

**Важно:** правка только markdown **не** меняет приложение. После согласования текстов нужно обновить JSON локалей (минимум `ru`, желательно зеркалить смысл в `en` и остальных). Смена языка UI у пользователя **перезапишет** встроенные `lazy-v1` / `pro-v1` из пакета локали.

Ограничения импорта колоды: ≤9 карт, id `[a-zA-Z0-9_-]{1,64}`, файл ≤ 512 KB.

## 9. Контракт для ИИ, который правит промпты карт

Пиши/меняй `prompt` так, чтобы агент в Cursor:

1. Делал **ровно роль карты** (план без кода; work — один шаг; fix — минимум; polish — до 9–10).
2. Для оценочных/тест/фикс/доводка/полный цикл — заканчивал ответ строкой `KEYCODE_SCORE: N`.
3. Держал шкалу: &lt;7 redo, 7–8 ок идти, 9–10 цель «Доведи».
4. Не раздувал scope и не предлагал «переписать всё», если хватает точечных правок (особенно hobby).
5. В pro — жёстче: acceptance, регрессии, findings, merge-ready тон.
6. В `summary` — только 4 блока статуса, без кода и без `KEYCODE_SCORE`.
7. Сохранял `id` / hotkey / image, если задача — только текст промпта.

Тон:

- **Хобби** — просто, без лишней инженерии, «хобби-проект».
- **Продакшен** — кратко, строго, без воды, критерии приёмки и риски.

## 10. Чего нет в v1 (чтобы не выдумывать)

- Автовыбор карты нейросетью (есть только rule-based glow).
- Облачный аккаунт / Funnel / marketplace.
- Адаптеры не-Cursor IDE как продукт.
- Разная формулировка одной карты на разные цели за один клик.
- Больше 9 карт в колоде.

---

## 11. Минимальный чеклист после правок колоды

- [ ] JSON валиден, 1–9 карт, id уникальны.
- [ ] Карты со score по-прежнему требуют `KEYCODE_SCORE: N` в конце.
- [ ] `summary` без score и без кода.
- [ ] `polish` явно требует 9–10, не останавливаясь на 7–8.
- [ ] Хобби и pro не смешаны по тону.
- [ ] При необходимости обновлён `docs/decks-prompts-ru.md` и другие локали.
